# SmartGround - Cursor AI 协同开发规约与设计灵魂

## 1. 核心工作流：先请示，后执行 (绝不自作主张)
*   **STEP 1 (分镜设计)**：当开启一个新算法模块时，Cursor **绝对不允许**直接输出全量代码。必须先用文字向人类提出 **“动画分镜设计方案”**（由 Gemini 提供）。
*   **STEP 2 (具象化变量)**：设计方案中必须明确：用到几个游标（`PointerBlock`）、用到哪些独立暂存区（如 `ArrayBlock(id, val, "key")`）。
*   **STEP 3 (代码实现)**：只有在人类回复“方案通过”后，Cursor 才可以输出对应的 C++ 代码。

## 2. 视觉与教学美学 (灵魂所在)
*   **拒绝无意义的高亮堆砌**：不要把比较过的格子全标上颜色。高亮必须有明确意义（如：绿色=永久就绪/有序，红色=当前焦点，黄色=正在扫描/比较）。
*   **物理隐喻**：数组的交换、平移绝不是简单的数据互换。必须使用 `FloatingText` 做抛物线或直线的“飞入特效”。元素离开原位后，原位置必须变成**灰色无数字的“空洞”**，直到新元素填入。
*   **自定义标签与坐标系**：
    *   使用 `ArrayBlock(id, val, "label")` 来替代丑陋的界外 ID，用 `"key"`, `"val"`, `"pivot"` 等符合代码语义的字符做标签。
    *   `ArrayBlock` 的绘图原点已恢复为左上角 `(0,0)`，宽度 60。因此，所有的 `PointerBlock` 在设置 X 坐标时，**必须加上 30 的偏移量 (`x + 30`)** 才能完美指向方块正中心。

## 3. Qt 踩坑与全局补丁须知 (历史经验)
*   **包围盒越界裁剪问题**：Qt 的 `boundingRect()` 必须比实际绘制的图形大一圈。如果在方块上方或下方画文字，包围盒必须向 y 轴负方向或正方向延展，否则文字会被无情削掉。
*   **播放重置**：MainWindow 在撤销和完整重播时按录制输入重新调用 `buildLayout()`。撤销期间 `m_animated=false`，布局与帧回放都必须即时完成。模块必须保证 `buildLayout()` 与 `runAlgorithm()` 使用相同输入；若模块支持不重建场景的独立帧重放，则首帧仍须使用全局重置动作并在 `renderFrame` 中恢复初始状态。

## 4. 动画架构重构规约 (DRY 原则)
*   **严禁在子类中硬编码动画**：不允许在每个 Module 的 `renderFrame` 中反复手写 `QPropertyAnimation` 和 `FloatingText` 的创建逻辑。
*   **提取公共动画引擎**：后续开发中，若遇到“数值飞入互换(Swap)”、“数值覆盖(Shift)”、“指针移动(PointerMove)”等通用视觉效果，Cursor 必须先将这些逻辑提取到 `AnimEngine` 或基类公共函数中。
*   **子类只负责调用**：子类的 `renderFrame` 应该非常清爽，只负责解析 `ActionType` 并调用公共动画接口。
