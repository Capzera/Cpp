## 零、通用视觉契约（10 个方案共用，先定死）

本批所有方案共用以下语义，任何一条新方案都不允许与之冲突：

| 语义 | 颜色 | 说明 |
|---|---|---|
| 待处理 / 未访问 | `#CEDAEA` 浅蓝灰 | 静止态，不参与焦点 |
| 当前焦点 | `#F5B942` 琥珀 | 任意时刻**最多 1 个**，正在读/正在写 |
| 已确定 / 成功 | `#5BC08A` 绿 | 结果落定，永久保留 |
| 冲突 / 失败 | `#E4572E` 朱红 | 冲突边、被淘汰、被拒绝 |
| 复用 / 分支 | `#7C6BD6` 紫 | 复用既有结构而非新建 |
| 淡出 / 淘汰 | `#9AA4B2` 灰 @0.45 | 已出局 |

**指针与光束约定**
- 垂直指针尖端落在目标单元格**宽度中心**；水平指针落在**竖直中点**。
- 光束一律沿**算法实际行进方向**运动；逆向遍历必须走 `playEdgeTravelFrom` / `playEdgeTraceFrom`（BUG-226 修复后的方向感知接口）。
- 任何指针/光束/飞行数字都**不得**穿越数组正文、也不得与标签文字重叠。

**分层布局（y 坐标带）**

| 带 | 用途 | 建议 y |
|---|---|---|
| L1 | 主图 / 树 / 网格 | 60 – 420 |
| L2 | 指针行（贴在数组上方） | 数组 y − 60 |
| L3 | 数组行 | 440 – 520 |
| L4 | 指针行（贴在数组下方） | 数组 y + 64 |
| L5 | 结论 / 脚本文本 | 600 – 700 |

**收尾完整性**：算法结束帧必须把队列 / 栈 / 暂存区恢复成「已清空」状态，指针隐藏，结论唯一。

## 1. 快速排序（`QuickSortModule`）

### 旧方案现状（已核对源码）

- 布局：单行数组 + 一个**独立浮空**的 `pivot` 格子（`ArrayBlock` 位于 `(400, 150)`，`showValue = false`）+ `i` / `j` 两个 `PointerBlock`（`logical_pos` 分别为 -1 / -2，用于消解重叠）。
- 帧序列：`AR_RESET` → `AR_HIGHLIGHT(l, r, depth)` → `AR_SCAN_MIN(l, 1000, pivot)` → `SQ_POINTER_MOVE(0/1, pos)` → `AR_COMPARE_SHIFT` → `AR_SWAP` → `AR_DONE` → `AR_RESET(-2)`。
- **已有**：`AR_HIGHLIGHT` 用「非当前区间进入阴影」表达递归区间；`AR_SCAN_MIN` 会把 pivot 值填进浮空格子。
- **缺口**：
  1. `depth` 只写进了**脚本文本**（「递归层 1: 处理子区间 [1,8]」），**画面上没有任何递归栈**——学生不知道自己在第几层。
  2. pivot 是一个**与数组脱离的浮空格子**，`AR_SWAP` 让数字飞过去，观感像「凭空出现的魔法数字」。
  3. 已归位的元素只有颜色区分，没有**锁定**语义（无法一眼看出「这个位置永久确定了」）。

### 新方案分镜

**静态布局**
- 主数组行：`a[1..n]`，下标标注在格子上方。
- **递归层带（Recursion Ribbon）**：数组**上方**一条水平带，每深入一层追加一个胶囊 `[1..8] → [1..4] → [3..4]`，当前层琥珀色，其余灰。
- `pivot` 取消浮空格子，改为**基准值徽标**，贴在当前区间左端格**上方**，紫色，写作 `pivot = 5`。

**帧序列**

| 帧 | 动作 | 教学注解 |
|---|---|---|
| `QS_RESET` | 全数组淡为浅蓝灰，递归带清空 | 「准备对 a[1..8] 排序」 |
| `QS_PUSH` | 递归带追加胶囊 `[1..8]` | 「进入第 1 层递归」 |
| `QS_PIVOT` | 左端格上方弹出 `pivot = 5` 徽标（紫色） | 「取区间首元素为基准」 |
| `QS_CURSOR` | `i` / `j` 指针分别滑到 `l` / `r` | 「i 从左扫，j 从右扫」 |
| `QS_CMP_J` | `j` 所在格亮琥珀，脚本报 `a[j] >= pivot`；成立则 `j` 左移一格 | 「j 找小于 pivot 的元素」 |
| `QS_CMP_I` | `i` 所在格亮琥珀，脚本报 `a[i] <= pivot`；成立则 `i` 右移一格 | 「i 找大于 pivot 的元素」 |
| `QS_SWAP` | 两格同时脉冲，两值**双向飞行**互换 + 涟漪 | 「交换越界元素」 |
| `QS_MEET` | `i` 与 `j` 相遇，同格叠印双指针 | 「i 与 j 相遇」 |
| `QS_PIVOT_HOME` | 基准值从徽标**飞回**相遇格落位，徽标淡出 | 「pivot 归位」 |
| `QS_LOCK` | 该格染**绿**并加锁定标记 | 「此位置永久确定」 |
| `QS_POP` | 递归带弹出当前胶囊，父级恢复琥珀 | 「返回上一层」 |
| `QS_DONE` | 全数组染绿，递归带清空 | 「排序完成」 |

**新增**：递归层带、基准值徽标、锁定语义。

## 2. 归并排序（`MergeSortModule`）

### 旧方案现状（已核对源码）

- 布局：主数组行 + 辅助数组 `aux` 行（两行并列，`m_auxBlocks`）。
- 帧序列：`AR_HIGHLIGHT(l, r, depth)` → `AR_SCAN_MIN` → `AR_COMPARE_SHIFT` → `AR_SWAP` → `AR_EXTRACT` → `AR_DONE` → `AR_RESET`。
- **关键问题**：**帧类型与快速排序完全共用同一套**（`AR_HIGHLIGHT` / `AR_SCAN_MIN` / `AR_COMPARE_SHIFT` / `AR_SWAP` / `AR_EXTRACT`）。快排是「双指针从两端逼近」，归并是「两段有序序列汇入单一输出」——但画面表现几乎一样，学生**无法区分这两个算法**。
- `AR_SCAN_MIN` 在归并里语义不成立（归并没有 pivot），属于借用快排帧的妥协。
- 辅助数组 `aux` 静静躺着，没有体现「合并输出缓冲区」的角色。

### 新方案分镜

**静态布局**
- 主数组行（上）+ 辅助数组行（下），两行**同宽对齐、列一一对应**。
- 每段已排序区间罩一个圆角括号 `⌒`，标注 `[2..5]`。
- 辅助行左侧标注 `temp[]（合并输出缓冲区）`。

**帧序列**

| 帧 | 动作 | 教学注解 |
|---|---|---|
| `MS_SPLIT` | 区间被一条**虚线**从中间劈开，左右两半各罩紫/蓝半透明框 | 「分成两半，递归处理」 |
| `MS_REC` | 虚线消失，左右半区递归 | |
| `MS_MERGE_OPEN` | 两段已排序区间各罩**绿框**，辅助行整体点亮为「接收区」 | 「准备合并两段有序序列」 |
| `MS_CMP` | 比较两段队首，两个格**同时**亮琥珀 | 「比较两段当前最小值」 |
| `MS_PICK_L` / `MS_PICK_R` | 较小者**飞入辅助行**下一格，落位后染绿并保留 | 「取较小的那个」 |
| `MS_APPEND` | 某段耗尽 → 剩余整段**整体平移**填入辅助行 | 「一段取完，剩下的直接搬过去」 |
| `MS_COPY` | 辅助行整体**下沉覆盖**主行（批量 `playMoveTo`），原主行先淡出 | 「把合并结果写回原数组」 |
| `MS_DONE` | 整行绿 | 「归并完成」 |

**关键差异**：与快排的**双指针逼近**明确区分 —— 归并是**两段各自出队、汇入单一输出**。

## 3. 堆调整（`HeapAdjustModule`）

### 旧方案现状（已核对源码）

- 布局：数组行 + 堆的树形展开（`m_treeNodes` / `m_treeEdges`）。
- 帧序列：`HG_RESET` → `HG_COMPARE(i, partner)` → `HG_SWAP(i, j)` → `HG_DONE`。
- **已有**：`HG_COMPARE` 会同时给数组格与树结点上色，`appendDescent` 画出祖先路径，`playEdgeTravel` 沿父子边走光束，脚本文本会说明「父节点关系 i/2」或「孩子关系 i*2 与 i*2+1」；`HG_SWAP` 用 `playSwapAnim`（数组）+ `playNodeSwapAnim`（树结点）+ `swapHeapValues` **真实交换了两处的值**。
- **缺口**：
  1. 「`左孩子 = 2k` / `右孩子 = 2k+1` / `父 = ⌊k/2⌋`」只出现在**脚本文本**里，画面上**没有常驻的公式条**。
  2. 树结点里**看不到下标**，数组格与树结点的对应关系要靠位置猜。
  3. 光束是「父子边高亮」，**值的迁移路径与光束不重合**（光束走边，值走结点），注意力被分散。

### 新方案分镜

**静态布局**
- 树结点内**直接写上下标**：`1` / `2` / `3` / `4` / `5` / `6` / `7`；值显示在下标下方（小字）。
- 数组行在树**下方**，每个数组格上方画一条**极细引导线**连到对应树结点（视觉映射，不挡视线）。
- 树下方**常驻公式条**：`左孩子 = 2k　右孩子 = 2k+1　父 = ⌊k/2⌋`。

**帧序列**

| 帧 | 动作 | 教学注解 |
|---|---|---|
| `HA_RESET` | 全树淡出，数组行归位，公式条淡入 | |
| `HA_TARGET` | 待调整结点放大脉冲（琥珀），其下标与值同时放大 | 「要调整的是 k 号结点」 |
| `HA_UP_COMPARE` | 与**父结点**的连线变琥珀，两个结点的值同时「标签互换」预演 | 「比较 k 与 ⌊k/2⌋」 |
| `HA_UP_SWAP` | 值**沿树边真正迁移**（子结点的数字飞向父结点，落位后旧值反向飞回） | 「值向上冒泡」 |
| `HA_STOP` | 若父结点已满足堆序 → 停在当前层，画绿色「✓ 满足堆序」徽标 | 「堆序恢复」 |
| `HA_DOWN_COMPARE` | 调整方向为下沉 → 与两个孩子**同时**连线变琥珀 | 「选较大的孩子」 |
| `HA_DOWN_SWAP` | 值沿树边向下迁移 | 「值向下沉」 |
| `HA_DONE` | 整棵树绿 | 「堆调整完成」 |

**关键差异**：光束与值迁移路径**重合**；下标与公式从「脚本文本」升级为「常驻画面元素」。

## 4. 0/1 背包（`Knapsack01Module`）

### 旧方案现状（已核对源码）

- 布局：`(n+1) × (W+1)` 的 DP 网格（`m_dpGrid`），行首有物品块（`m_itemBlocks`），行列各带坐标标签。
- 帧序列：`KN_RESET` → `KN_CANDIDATE(编码的源格, 编码的目标格, 候选值, 0/1)` → `KN_DECIDE(i, j, best, 0/1/2)`。
- **已有**：`KN_CANDIDATE` 会把源格上色并用 `playValueFlight(source->centerPos(), target, 候选值, 颜色)` **从源格飞向目标格**，颜色区分「不选（蓝）」与「选（橙）」。
- **缺口**：
  1. **两个候选被拆成两帧先后飞入同一个目标格**，观众看到的是「一个数飞进来，又被另一个数飞进来盖掉」，**看不到两者并排比较**。
  2. `KN_DECIDE` 是**直接赋值 + `playCellLanding`**，最终胜出的那个值**不是飞进来的**，而是自己冒出来的。
  3. 网格**没有转移来源标注**，事后无法回看「这个格子是从哪来的」。
  4. 没有「当前处理到第几个物品」的**全局进度指示**。

### 新方案分镜

**静态布局**
- DP 网格仍是主角：列宽自适应、行高加大。
- 网格**右侧**留一列「转移来源」注记（每格写 `← dp[i-1][j]` 或 `← dp[i-1][j-w]+v`）。
- 网格**下方**一条**物品进度带**：`物品1 ✓ → 物品2 ● → 物品3 ○`。

**帧序列**

| 帧 | 动作 | 教学注解 |
|---|---|---|
| `KB_ROW_OPEN` | 第 0 行全部置 0，浅绿描边 | 「不选任何物品，价值为 0」 |
| `KB_ITEM` | 进度带推进到第 i 个物品，物品图标从左侧滑入 | 「处理物品 i（重量 w，价值 v）」 |
| `KB_SRC` | 从 `dp[i-1][j]` 拉出**紫色细线**到 `dp[i][j]`，标注「不选」 | 「方案 A：不选这个物品」 |
| `KB_TAKE` | 从 `dp[i-1][j-w]` 拉出**绿色细线**到 `dp[i][j]`，标注「选：+v」 | 「方案 B：选这个物品」 |
| `KB_COMPARE` | 两条线上的源格**同时**亮琥珀，格内数字放大 | 「比较两个候选」 |
| `KB_WRITE` | 较大者**飞行落入** `dp[i][j]` 并染绿；另一条线淡出为灰 | 「取较大者写入」 |
| `KB_ROW_DONE` | 本行写完，行首标绿勾 | 「第 i 行完成」 |
| `KB_FINAL` | 只高亮 `dp[n][W]`，其余淡为浅蓝灰 | 「答案 = dp[n][W]」 |

**关键差异**：从「一个一个覆盖」升级为「**两条候选路径并排对比 + 胜者飞行落位**」。

## 5. KMP（`KMPNextModule` + `KMPMatchModule`）

### 旧方案现状（已核对源码）

- 布局：主串 `s` 行 + 模式串 `p` 行 + `pi[]` 行，三行共用同一 x 基准与列宽；`i` / `j` 两个指针。
- 帧序列：
  - `KMPNextModule`：`KMP_RESET` → `KMP_SET` → `KMP_COMPARE(i, j+1, ...)` → `KMP_FALLBACK(i, j, fallback)` → `KMP_SET(i, j, pi值)` → `KMP_DONE`。
  - `KMPMatchModule`：`KMPM_RESET` → `KMPM_COMPARE` → `KMPM_FALLBACK` → `KMPM_ADVANCE` → `KMPM_HIT` → `KMPM_DONE`。
- **已有**：`KMP_FALLBACK` 会把 `j` 指针移到 `m_charCells[fallback]`，`pi[]` 数值写入并 `playCellLanding` + `playCellRipple`；`KMPM_FALLBACK` 会用 `layoutPatternRow(offset)` **整体平移模式串**，把失配格染成浅蓝底。
- **缺口**：
  1. `pi[i] = k` 的**含义**（模式串前 i 个字符的最长相同真前后缀长度）**完全没有可视表达**，只是一列数字。
  2. 计算 `pi[i]` 时，「为什么 fallback 到 k 之后 `p[i] == p[k]` 就成立」这件事**只在脚本文本里**，画面上没有 `p[i-k..i-1]` 与 `p[0..k-1]` 的**对应括线**。
  3. 匹配失配时，已匹配前缀**没有变灰**（`KMPM_FALLBACK` 把所有模式串格刷白），观众看不出「已经比对了多少个字符」。

### 新方案分镜

**静态布局**
- 主串 `s`（上）、模式串 `p`（中）、`pi[]`（下），三行列宽一致、下标对齐。
- 模式串**下方**一条**匹配条**：每个字符格下一条横向色条，长度 = `pi` 值（长度编码可视化）。
- 当 `pi[j] = k` 时，模式串下方画一条**跨 k 格的紫色括线**，把 `p[j-k..j-1]` 与 `p[0..k-1]` 连起来。

**帧序列**

| 帧 | 动作 | 教学注解 |
|---|---|---|
| `KP_NEXT_BUILD` | 逐个构造 `pi[]`：已知 `pi[j-1] = k` → 紫色括线连接 `p[j-k..j-1]` 与 `p[0..k-1]` → 确认 `p[j] == p[k]` 则 `pi[j] = k+1` | 「求最长相同真前后缀」 |
| `KP_NEXT_FALLBACK` | `p[j] != p[k]` → `j` 跳到 `pi[k-1]`，括线随之前移 | 「失配，退到更短的相同前后缀」 |
| `KP_NEXT_DONE` | 全部 `pi` 就位，括线逐条淡出 | |
| `KP_MATCH_START` | 模式串滑到主串第 0 位 | 「开始匹配」 |
| `KP_MATCH_OK` | `s[i] == p[j]` → 对齐格染绿，模式串对应格同步染绿 | 「匹配成功，继续」 |
| `KP_MATCH_FAIL` | `s[i] != p[j]` → 该格染**朱红**；**已匹配的前缀格染灰但保留绿痕**；画两处标记（红叉在失配位，绿钩在已匹配前缀末端） | 「失配了」 |
| `KP_FALLBACK` | 按 `pi[j]` 把模式串**整体左移**，左移后新对齐的格亮琥珀 | 「利用 next 数组回退，避免重新比较」 |
| `KP_TEXT_DONE` | 输出匹配起点位置（绿块落入结果区） | 「找到匹配」 |

**关键差异**：把 `pi[]` 从「数字表」变成「**可读的边框图**」—— 这正是 KMP 最难讲的部分。

## 6. 拓扑排序（`TopologicalSortModule`）

### 旧方案现状（已核对源码）

- 布局：DAG 图 + 入度数组 `m_degreeBlocks` + 队列 `m_queueBlocks`（带 head / tail 指针）+ 结果序列 `m_orderBlocks`。
- 帧序列：`TS_RESET` → `TS_DEGREE(u, v, value)` → `TS_ENQUEUE` → `TS_DEQUEUE` → `TS_OUTPUT` → `TS_SCAN_EDGE(u, v, value)` → `TS_BLOCKED` → `TS_FINISH`。
- **已有**：`TS_DEGREE` 会把对应图上那条边染蓝并 `playEdgeTravel` 走光束；`TS_SCAN_EDGE` 把边染**橙色**并走光束，同时 `indegree` 格数字更新；入度归零时结点 `playDiscover`。
- **缺口**：
  1. 边被「删除」时**没有删除标记**（没有 ✕、没有变灰），只是改了个颜色并让光束跑一遍，学生看不出「这条边已经处理完了」。
  2. 入度数组与图中结点**没有对齐关系**（数组顺序 vs 结点位置），要靠数字对应去猜哪个格是哪个点。
  3. 「入度为什么减 1」的**因果链断了**：光束走了，但看不出「这条边被删 → 所以它的终点入度 -1」是同一件事。
  4. 结果序列 `order[]` 只是一列数字，缺少「这个点为什么此刻能出队」的标记。

### 新方案分镜

**静态布局**
- DAG 图（主）+ **入度表 `indeg[]`**（下方，与图中结点**同序对齐**，每列上方标结点号）。
- 每条已处理的边**中点**挂一个小徽标，显示「删边后终点入度 -1」。

**帧序列**

| 帧 | 动作 | 教学注解 |
|---|---|---|
| `TS_INI` | 逐边统计入度，`indeg[]` 对应格从 0 数起 | 「统计每个结点的入度」 |
| `TS_ZERO` | 所有入度为 0 的结点染**琥珀**并罩「✓」徽标 | 「这些点可以先做」 |
| `TS_POP` | 选一个零点 → 弹出**结果序列条**（右侧竖排），结点染绿 | 「加入拓扑序」 |
| `TS_EDGE_DEL` | 该结点的出边**逐条**变灰并打 ✕；每删一条，对应终点结点的 `indeg` 格**减 1 并闪烁**，边中点徽标显示 `-1` | 「删边 ⇒ 终点入度减 1」 |
| `TS_NEW_ZERO` | 某终点入度减到 0 → 立即染琥珀并打 ✓ | 「新的零点出现了」 |
| `TS_CYCLE` | 若还有点未处理但无零点 → 剩余结点染红并画**红色环** | 「有环！拓扑序不存在」 |
| `TS_DONE` | 结果序列条全部绿 | 「拓扑序 = ...」 |

**关键差异**：入度递减与**图上具体边的删除**绑定成同一个动作。

## 7. 朴素 Dijkstra（`DijkstraNaiveModule`）

### 旧方案现状（已核对源码）

- 布局：图 + `dist[]` 数组 + `done[]` 数组 + `parent[]` 数组；两个指针 `m_pickPointer`（选点）与 `m_relaxPointer`（松弛目标）。
- 帧序列：`DJ_RESET` → `DJ_SCAN(...)`（两种语义：`group[0]==1` 表示「沿边松弛」，否则表示「扫描未确定点」）→ `DJ_SELECT(u, round)` → `DJ_RELAX(u, v, candidate, old)` → `DJ_UNREACHABLE` → `DJ_FINISH`。
- **已有**：`DJ_SCAN` 沿边走光束（`playEdgeTravel`）并把目标结点染琥珀；`DJ_RELAX` 用 `playValueFlight` 把新距离从结点飞到 `dist[]` 格。
- **缺口**：
  1. **「为什么选它」完全不可见**：`DJ_SELECT` 只是把结点染绿 + `playDiscover`，学生看不到「它是因为 `dist` 最小才被选中」这个**选择依据**。这是朴素 Dijkstra 最核心的教学点。
  2. 松弛时**旧值直接被替换**，没有「旧值 vs 新值」的对比（旧的 `∞` 消失得无影无踪）。
  3. `DJ_SCAN` 一个帧类型承担了两种语义（扫描未确定点 / 沿边松弛），靠 `group` 标志区分，语义负担重。

### 新方案分镜

**静态布局**
- 图 + `dist[]`（下）+ **候选最小值尺**（右侧竖列）：把「未确定点」按当前 `dist` 值排成刻度尺，指针指向最小者。已确定点从尺上移除（划掉）。

**帧序列**

| 帧 | 动作 | 教学注解 |
|---|---|---|
| `DS_RESET` | `dist[src] = 0`，其余 `∞`（灰） | 「初始化」 |
| `DS_PICK_SCAN` | 候选尺上未确定点按 `dist` 排序显示，最小者滑到尺顶 | 「找未确定点中 dist 最小的」 |
| `DS_PICK` | 该点染琥珀 → 罩「✓ 已确定」→ 染绿，`dist[]` 对应格同步 | 「永久确定」 |
| `DS_RELAX_CHECK` | 沿出边 `u→v` 走光束（**按算法行进方向**，用 BUG-226 修复后的 `playEdgeTravelFrom`），`dist[v]` 格亮琥珀 | 「尝试松弛 v」 |
| `DS_RELAX_NEW` | 若更短：**旧值（`∞` 或旧数）淡出**，新值**飞入**该格 | 「dist[v] 变小」 |
| `DS_RELAX_KEEP` | 若不变：候选值被**红线划掉**，`dist[v]` 不动 | 「不变，保持」 |
| `DS_UNREACH` | `∞` 格染灰 | 「不可达」 |
| `DS_DONE` | 全部确定点绿 | 「最短路确定」 |

**关键差异**：新增「候选最小值尺」，把「**为什么选它**」显式化。

## 8. Kruskal 最小生成树（`KruskalModule`）

### 旧方案现状（已核对源码）

- 布局：图 + `parent[]` 数组 + **边表**（`m_edgeBlocks`，已按权值排序）+ `m_edgePointer`。
- 帧序列：`KR_RESET` → `KR_CHECK(u, v, w, index, {rootU, rootV})` → `KR_ACCEPT(u, v, w, index, group)` → `KR_REJECT(u, v, w, index, {rootU})` → `KR_FINISH` / `KR_DISCONNECTED`。
- **已有**：`KR_CHECK` 会把 `rootU` 染琥珀、`rootV` 染蓝，并在两端之间用 `playEdgeTravel` 走一道探测光束；`KR_ACCEPT` 把 `parent[child] = root` 直接赋值，并给合并进来的所有结点**统一染色**（`QColor::fromHsv` 按根编号生成色相）；`KR_REJECT` 把边刷灰 + `playEdgeSweep`。
- **缺口**：
  1. **`find` 的路径压缩过程不可见**：`KR_CHECK` 直接给出 `rootU` / `rootV` 结果，中间「沿 `parent` 链逐跳上溯」的过程**完全跳过**——这是 Kruskal 最难懂的一步。
  2. `parent[child] = root` 是**一步到位**赋值，没有画出「旧的父 → 新的根」这条**改写动作**。
  3. 被拒绝的边只刷灰，**没有画出它形成的环**，「为什么必须舍弃」缺少反证。
  4. 结点颜色虽然按集合区分，但**没有画出集合的树形结构**，看不出「哪些点挂在同一个根下」。

### 新方案分镜

**静态布局**
- 图（主）+ `parent[]`（下）+ **并查集森林树形图**（右侧）：每个集合画成一棵小树，根用紫色。

**帧序列**

| 帧 | 动作 | 教学注解 |
|---|---|---|
| `KU_SORT` | 所有边按权值排序，边表**重排**（边从原位飞向新位），排序轴标注「按 w 升序」 | 「贪心前提：从小到大」 |
| `KU_FIND_START` | 选中边 `u—v`，从 `u` 出发沿 `parent` 链**逐跳**点亮结点，紫色链 | 「find(u)：沿父指针上跳」 |
| `KU_FIND_ROOT` | 到达根（紫色），显示 `root(u) = r` | 「u 属于集合 r」 |
| `KU_FIND_V` | 对 `v` 同样演示 | 「v 属于集合 s」 |
| `KU_COMPRESS` | 沿途每个结点的 `parent` **逐个改写**为根，每改一个画一道紫色飞线；旧链保留虚线残影 | 「路径压缩：沿途都指向根」 |
| `KU_SAME` | 若 `r == s` → 该边染**朱红**，并在图上画出**红色闭合环**（沿树路径 + 该边） | 「形成环，必须舍弃」 |
| `KU_MERGE` | 若 `r != s` → 两棵森林小树合并（一边整体飞向另一边），`parent[child] = root` 画紫色飞线 | 「按秩/按大小合并」 |
| `KU_ACCEPT` | 该边染**绿**并加粗 | 「接受这条边」 |
| `KU_FINISH` | MST 边绿、其余灰 | 「MST 完成，总权值 = ...」 |

**关键差异**：`find` 的**逐跳路径压缩**可视化 + 成环边的**红环**反证。

## 9. 并查集路径压缩（`DSUPathCompressionModule`）

### 旧方案现状（已核对源码）

- 布局：森林图（`m_nodes` + `m_edges`，每个结点 `setSubLabel("pa=N")`）+ `pa[]` 数组 + `sz[]` 数组 + `x` 指针。
- 帧序列：`DP_RESET` → `DP_FIND(x, 0, pa[x], {path})` → `DP_FIND(x, 1, x, {path})`（找到根）→ `DP_COMPRESS(x, 0, x, {path})`（整链高亮）→ `DP_COMPRESS(node, 1, x, {path})`（**逐个结点改写**）→ `DP_DONE`。
- **已有**：`DP_FIND` 会把路径上所有结点染 `kDpPath` 并逐个 `playNodeRipple`；`DP_COMPRESS` 逐结点执行 —— 把 `pa[]` 对应格改成根并 `playCellLanding`，把指向根的那条边染紫并 `playEdgeTravel`，其余相邻边刷淡。
- **缺口**：
  1. **没有「压缩前 / 压缩后」的对照**：路径被压扁的过程只能靠「边变紫」感知，学生看不到**树高从 h 变成 1** 这个结构性结果。
  2. 旧链**没有残影**（被改写的边直接刷淡），看不到「原来是这么长的链」。
  3. `sz[]` 数组全程只是摆设——**按秩合并**的语义没有用上。
  4. `DP_DONE` 把所有结点和边染成同一个金色，**结构信息全丢**。

### 新方案分镜

**静态布局**
- `pa[]`（上）+ `sz[]`（中）+ 森林图（下）。
- 森林图**右侧**留一条**树高标尺**：竖向刻度记录当前最大树高，压缩发生时标尺**从 h 缩到 1**。

**帧序列**

| 帧 | 动作 | 教学注解 |
|---|---|---|
| `UF_RESET` | `pa[i] = i`，每个结点自成一棵单点树 | |
| `UF_FIND_CHAIN` | 沿 `pa` 链逐跳点亮，路径紫色 | 「查找根」 |
| `UF_FIND_ROOT` | 到达根（紫），树高标尺显示当前高度 h | 「根是 r」 |
| `UF_COMPRESS` | 链上每个结点的 `pa` **逐个改写**为根，每改一个画一道紫色飞线；**旧链保留虚线残影** | 「路径压缩：沿途都指向根」 |
| `UF_HEIGHT` | 树高标尺从 h **动画收缩**到 1 | 「整棵树被压扁成一颗星」 |
| `UF_UNION` | 两个集合合并，**按 `sz` 决定**挂哪边（`sz[]` 对应格高亮显示比较过程）；挂接瞬间画紫色飞线 | 「小集合挂到大集合下」 |
| `UF_DONE` | 森林保持**结构着色**（每棵树一个色相），而不是全部染金 | 「并查集完成」 |

**关键差异**：**压缩前/后对照 + 旧链虚线残影 + 树高标尺**，让「压缩」这件事本身可见。

## 10. 埃氏筛（`SieveOfEratosthenesModule`）

### 旧方案现状（已核对源码）

- 布局：数字行 `m_cells`（`2..n`）+ 质数栏 `m_primeBlocks` + 扫描脚本文本 `m_scanText`。
- 帧序列：`SV_RESET` → `SV_PRIME(i)` → `SV_SCAN(i, 数量, multiples)` → `SV_CROSS_BATCH(i, 数量, multiples)` → `SV_PRIME_LIST(质数集)` → `SV_DONE`。
- **已有**：`SV_CROSS_BATCH` **不是一次性划完**——它用一个 `QVariantAnimation` 按 `targets.size() * 28ms` 的节奏**逐个**执行 `applyCross(block)` 并 `playCellRipple`，视觉上是「一道流动的红线依次划过一批倍数」。
- **缺口**：
  1. **「为什么从 `i*i` 开始」是本模块的灵魂，却只写在一句脚本文本里**（「从 i*i = 9 起，划掉 9 的 3 个倍数」），画面上没有任何**空间化的表达**。
  2. 扫描指针 `i` **没有指针在数组上滑动**，只靠脚本文本「当前素数 7」告知学生扫到哪了。
  3. `SV_PRIME_LIST` **一次性**吐出全部质数，没有「一个一个被确认并归档」的积累感。
  4. 被划掉的数（合数）与**未被扫到的数**视觉上区分不够明确。

### 新方案分镜

**静态布局**
- 上方：数字行 `2..n`。
- 下方：`st[]` 标记行，与数字行**同列对齐**。
- 右侧：**质数收集栏**（竖排），已确认的质数逐个落入。
- 数字行**左侧**留一条**扫描指针轨**：`i` 指针沿轨滑动。

**帧序列**

| 帧 | 动作 | 教学注解 |
|---|---|---|
| `SI_RESET` | `st[]` 全 0，数字行浅蓝灰 | |
| `SI_SCAN` | `i` 指针沿轨右滑，每格亮琥珀 | 「逐个检查 i」 |
| `SI_PRIME` | 若 `st[i] == 0` → 该格染**绿**并**飞入**右侧质数栏 | 「i 是质数，收进列表」 |
| `SI_START` | 脚本显示「从 `i*i` 开始划」，同时在数字行上画出**一段从 `i*i` 起的紫色下划线区间** | 「更小的倍数已被前面的质数划掉了」 |
| `SI_CROSS_ONE` | **逐个**划掉 `i*i, i*i+i, ...`：每个被划数字变**灰 + ✕ + 删除线**，`st[]` 对应格置 1 并闪烁 | 「标记为合数」 |
| `SI_CROSS_DONE` | 本轮划掉数量汇总 `+k` | |
| `SI_LIST_DONE` | 质数栏全部绿 | 「质数集合 = ...」 |
| `SI_DONE` | 结论「时间复杂度 O(n log log n)」 | |

**关键差异**：`i*i` 的**剪枝理由**从脚本文本升级为**空间化的紫色区间标记**；质数**逐个归档**。
