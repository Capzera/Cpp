# SmartGround 动画与视觉美学规范 (Animation Aesthetics Bible)

> **定位**：本文件是 SmartGround 全部动画模块的**视觉宪法**。所有新模块、动画深化、UI 控件改动都必须先在此找到对应条款，再动手写代码。
> **关联**：`.cursorrules` 第 2/4 节（动画架构 DRY）、`Cursor_Workflow.md` 第 2 节（教学美学灵魂）、`src/ui/UiTheme.h`（设计令牌）。
> **维护**：新增视觉概念时先改本文件，再改代码；改代码前先确认本文件已有对应条款，避免同一效果在不同模块里各写一套。

---

## 0. 三条不可违背的底线

1. **语义先于装饰**：任何颜色、动效、形状都必须回答「它在表达算法的哪一个事实」。回答不了的元素一律不加。
2. **一处实现，全局复用**：可复用的视觉效果必须先沉淀进 `IModule` 基类或 `src/ui/widgets/`，禁止在模块里手写 `QPropertyAnimation`。
3. **状态必须收尾**：每个动画流程结束时，画面必须回到一个**自洽的终态**（队列清空、指针归位、临时结构复位）。残留半截状态即为缺陷。

## 1. 色彩语义表 (Color Semantics)

全项目统一使用这一套「颜色 = 事实」的映射。新增颜色必须先在此登记语义，禁止模块内临时起名。

| 颜色 | 语义 | 取值参考 |
|---|---|---|
| **蓝** | 0 / 偶数层 / 已染色（第一部分） | `#78AFEB` |
| **橙** | 1 / 奇数层 / 已染色（第二部分） | `#F5C391` |
| **绿** | 永久就绪 / 已确定 / 成功 / 已匹配 / 答案 | `#8CCDA5` `#34C759` |
| **黄** | 正在扫描 / 当前比较焦点 / 待处理 | `#FFD68A` `#FFCE9E` |
| **红 / 绯** | 冲突 / 失败 / 死路 / 违规 | `#F08278` `#E2573C` |
| **紫** | 延迟边 / 特殊标记 / 模式分支 | `#9E7AD6` |
| **灰** | 已淘汰 / 已出栈 / 空槽 / 失活 | `#CDD2DA` `#FAFCFC` |
| **靛** | 贪心对照（次优解 / 反例） | `#8E8FC7` |

**规则**
- 同一时刻画面上**同时活跃的强调色不超过 3 种**。第 4 种必须降级为灰。
- 「红」只能表示**真的错了**（冲突、死路、失败）。不要用它表示「当前正在处理的普通元素」。
- 「绿」只能表示**最终成立**（答案、就绪、匹配成功）。不要用它表示「刚刚处理过」。
- 淘汰 / 空槽必须是**无数字的灰**，不要用半透明残影保留原值。

## 2. 运动语义表 (Motion Semantics)

### 2.1 边的四种运动

| 运动 | 实现 | 用途 |
|---|---|---|
| **行进 (Travel)** | `playEdgeTravel(edge, color, ms)` | 光束从 `source` 扫到 `dest` |
| **反向行进 (Travel From)** | `playEdgeTravelFrom(edge, color, fromNodeId, ms)` | 光束**从指定节点出发**沿边扫过。无向边双向访问时必须用这个，否则第二次访问方向与第一次相同，是**语义错误** |
| **绘制生长 (Grow)** | `playEdgeGrow(edge, ms)` | 边从头到尾被"画出来"（建树 / 生成边） |
| **描迹 (Trace)** | `playEdgeTraceFrom(edge, color, fromNodeId, ms)` | 亮点沿线走一遍后消失（延迟边 / 试探） |

> **强制条款**：任何"从 u 走到 v"的语义，**必须**使用 `playEdgeTravelFrom(edge, color, u, ms)` 传入**起点节点 id**，而不是 `playEdgeTravel`。
> `playEdgeTravel` 只适用于「边本身从 source 生长到 dest」的场景（此时 source 即起点）。
> 无向图上双向访问同一条边时，第二次必须让光束**反向**。

### 2.2 节点的五种运动

| 运动 | 实现 | 用途 |
|---|---|---|
| 涟漪唤醒 (Wake) | `playNodeWake(node, color, r, ms)` | 节点被"点名"，从中心扩散一圈光环 |
| 缩放脉冲 (Pop) | `playNodePop(node, peak, ms)` | 节点值发生变化时的轻微弹跳 |
| 出现 (Appear) | `playNodeAppear(node, ms)` | 新节点从透明淡入 |
| 聚焦环 (Focus) | `playFocusRing(node, color, ms)` | 节点被设为焦点 |
| 数值飞行 (Flight) | `playValueArcFlight / playValueDropInto` | 数值从 A 处抛物线飞到 B 处 |

### 2.3 指针的运动

- 指针**尖端永远落在锚点**（格心 / 节点圆周），不得横向平移尖端。
- 指针标签**沿自身轴线**堆叠避让（垂直指针上下分行，水平指针左右让位），不得脱离轴线。
- 指针只能**指向一个当前槽位**。两个语义不同的指针（如 `head` / `tail`）指向同一格时，必须用**不同的杆长**把它们在视觉上分层。

> **强制条款（指针必须平移，禁止瞬移）**
>
> 指针换锚点时**必须**播放一段 `pos` 缓动动画（380–400 ms），让学生看清「指针从哪走到哪」。
> 实现上的硬性要求：`IModule::syncPointerTips()` 在每帧收尾时**不得无条件**执行 `stopAnimFor(ptr) + setPos(tip)`，
> 否则刚启动的平移动画会被当场掐断，指针退化为**瞬移**。
> 正确做法：先扫描 `m_animRegistry`，若存在**正在运行**且**终点等于**目标 tip 的 `pos` 动画，则**跳过吸附**，让缓动曲线自然跑完；
> 只有确认没有匹配动画时才允许硬吸附。
> **判据**：一个模块里出现「指针换位置但画面上没有任何移动过程」，即为违反本条款。

### 2.4 轨迹 (PathTrail)

`PathTrail` 用于**有序路径**的一笔描画（欧拉路径、增广路、树直径、奇环）。
- 描画顺序必须与算法顺序一致。
- 描画结束后轨迹**保留**，作为最终结论的视觉证据。

### 2.5 时长基准

| 场景 | 时长 |
|---|---|
| 指针移动 | 380 – 400 ms |
| 数值飞行 / 抛物线 | 460 – 560 ms |
| 节点脉冲 | 240 – 340 ms |
| 涟漪扩散 | 420 – 640 ms |
| 边行进 / 描迹 | 400 – 560 ms |
| 轨迹一笔描 | 700 – 760 ms |
| 文本替换 | 立即（不做淡入淡出，避免拖沓） |

所有运动使用 `InOutCubic` 或 `OutCubic` 缓动。**禁止线性缓动**。

## 3. 布局与留白规范 (Layout)

### 3.1 画布分层（自上而下）

```
y=18    标题 / 数学描述行（m_mathText，单行，Consolas）
y=140   算法主体（图 / 树 / 网格）——视觉重心
y=440+  状态数组行（col[] / deg[] / dist[]）
y=560+  辅助结构行（q[] 队列 / stk[] 栈 / path[] 答案）
y=630+  结论文本（结论 + 原因）
```

**规则**
- **主体与辅助结构之间至少留 60px 垂直净距**，避免指针标签与数组下标打架。
- **同一行只放一种语义**。贪心解与反例解必须**分两行**，绝不并排。
- 指针标签底部**不得越过画布下边界**（当前基准 700px）。越界即为布局缺陷。

### 3.2 数组单元格

- 数组下标**必须在单元格上方**，水平居中，与顶边框保持 6px 净距。
- 单元格内的值**必须双向居中**（`Qt::AlignCenter`），字号 14。
- 数组行起点 x 坐标要留出左侧标签列的宽度（≥ 140px），标签写在最左侧。

### 3.3 队列行的三段式

队列是本项目最常出现也最容易出错的结构，标准画法：

```
  标签 "q[] 队列"  ...  [槽0][槽1][槽2][槽3][槽4]...
                                    ↑
                                 head 指针（红，杆短）
                                 tail 指针（蓝，杆长）
```

- 两个指针都在队列行**下方**，箭头**朝上**指向各自的槽位下沿。
- `head` 与 `tail` 用**不同杆长**（建议 28 / 44）分层，标签才不会重叠。
- **队列出队后必须清空槽位**（`showValue = false`），流程结束时**整行清空且两个指针隐藏**。

### 3.4 递归区间的「裂开 — 拼接」语义（归并排序类）

递归分治类算法的画面**不得**始终保持一条完整数组。分治过程必须在视觉上**真的切开**。

```
初始:  [8][3][5][1][7][2][6][4]           ← 淡白（未排序）
裂开后: [8][3] | [5][1] | [7][2] | [6][4]  ← 缝 = 递归边界
合并完: [1][3][5][8][7][2][6][4]           ← 整段转深绿（已就绪）
```

**规则**

- **裂开 (Split)**：在递归边界处让出 **≥ 20px 的物理缝隙**，并用 `playMoveTo` 把两段**平移**分开（不是瞬移，不是缩放）。缝隙是「递归边界存在」的唯一视觉证据。
- **拼接 (Splice)**：当一个区间**合并完成**时，缝隙必须**合上**，两段重新贴成一个连续单元，并整段染成**已就绪绿**。合缝与染色**必须在同一帧**发生，学生才能建立「这一段已经排好了」的因果。
- **分色即状态**：

| 颜色 | 语义 | 参考 |
|---|---|---|
| 淡白 | 该区间**尚未排序** | `#FAFCFC` |
| 浅蓝 | 递归的**左半段** | `#DCE9F7` |
| 浅紫 | 递归的**右半段** | `#EAE0F4` |
| 深绿 | 该区间**整段已排好序** | `#8CCDA5` |

- **辅助缓冲行 (temp[])**：归并类算法必须有独立的 `temp[]` 行承接写入过程。数值从源格**飞入** temp 格，源格转灰表示「已取走」。禁止直接原地改值。
- 同一时刻**同时活跃的强调色不超过 3 种**。左浅蓝 / 右浅紫 / 已就绪绿恰好占满 3 种，符合第 1 节规则。

### 3.5 并查集的双数组同步语义

并查集是「**一个逻辑结构 + 两份镜像状态**」的教学结构，画面必须让三者同时可读：

```
森林图（结构）          pa[] 数组（父指针）      sz[] 数组（集合大小）
   ○────○────○             [0][1][2][3][4]         [1][1][1][1][1]
   │    │    │
 根    子    根
```

**规则**

- **`pa[]` 必须初始全为自身下标**（不是全 0、不是全 1）。这是「每个点的父亲是自己」的唯一视觉证据。
- **`sz[]` 必须初始全为 1**，与 `pa[]` 等宽等列对齐，两个数组**逐格对齐**，禁止上下错位。
- **父亲改变**：子根的 `pa` 格**即时改写**为新父下标，对应的森林边**改接**到新父（用 `GraphEdge::repointDest()`），并给新父染**绿**、被合并的子根染**橙**。
- **大小变动**：`sz[parent]` 改变时必须**单独一帧**呈现变更后的数值并落位脉冲，把「合并导致集合变大」与「指针改接」在时间上**分开**，学生才能看清因果。
- **路径压缩**：被压缩的路径用**紫**色（延迟 / 特殊标记语义，见第 1 节）高亮，边**当场改接**到根，不得重建整棵树。

## 4. 控件语义规范 (Control Semantics)

### 4.1 开关 (MyToggleSwitch) —— 状态与位置的对应关系

**这是硬性条款，全项目所有 toggle 统一执行：**

> **开关滑块在右侧 = 该状态「开启 / 选中」。滑块在左侧 = 该状态「关闭 / 未选中」。**
> **文字标签与滑块的相对位置必须符合直觉：**

| 控件 | 左侧文字 | 右侧文字 | 默认（关闭）时滑块 | 开启时滑块 |
|---|---|---|---|---|
| 图的类型 | 有向图 | 无向图 | 滑块在**左**，左侧「有向图」高亮 | 滑块在**右**，右侧「无向图」高亮 |
| 高亮延迟边 | 关 | 开 | 滑块在**左**，左侧「关」高亮 | 滑块在**右**，右侧「开」高亮 |

- 滑块**靠右**时：右侧文字为**当前生效状态**，用 `textPrimary` 深色；左侧文字为未生效状态，用 `textMuted` 浅色。
- 滑块**靠左**时：左侧文字为**当前生效状态**，用 `textPrimary`；右侧用 `textMuted`。
- 语义是**互斥选择**的 toggle，**必须**用 `ModuleField::makeSegment`（分段控件），不得用 toggle。

### 4.2 分段控件 (MySegmentedControl)

- 用于**互斥的多态选择**（如 Trie 的「插入 / 查询 / 字典序」）。
- 选中项必须有明确视觉差异（底色 + 文字色双重变化），不能只靠文字颜色。

### 4.3 文字输入

- 文本输入框必须**在 `editingFinished` 时**才写回状态，避免每敲一个字符就触发整场算法重跑。
- 宽度按内容上限设定（72px 足够放 4 – 6 位数字），过宽会破坏面板对齐。

### 4.4 禁止事项

- 禁止 `QPushButton` / `QRadioButton` / `QCheckBox` / `QComboBox` / `QTextEdit` 直接呈现给用户。
- 禁止在业务代码里写死十六进制色值，一律取 `UiTheme`。

## 5. 交互状态的完整性 (State Completeness)

每条算法流程都必须满足以下**收尾条款**：

1. **临时结构复位**：队列清空、栈清空、辅助数组回到初始值。
2. **指针归位**：所有指针要么指向算法结束时的真实位置，要么隐藏（`opacity = 0`）。
3. **结论落地**：屏幕上必须留下一句**明确的结论文本**（是 / 不是 / 最优值是多少 / 为什么）。
4. **重放幂等**：从任意帧跳转后继续播放，画面状态必须自洽（不得残留上一次的中间态）。
5. **撤销兼容**：`m_animated == false` 时**不得创建任何 `QPropertyAnimation`**，状态必须瞬时到位。

## 6. 文案规范 (Copy)

- **算法语句**用代码书写：`col[v] = col[u] ^ 1`。
- **解释语句**用自然语言：`节点 v 与 u 相邻，染成橙色（1）`。
- 结论文本必须**说人话**：「该图不是二分图」优于「BP_FINISH = 0」。
- 错误提示必须指出**原因**与**后果**，不只是「失败」。

---

## 7. 动画帧设计 (Frame Design)

- **一帧 = 一个可讲解的事实**。不要把「染色 + 入队 + 画边」塞进同一帧。
- 帧类型命名统一 `<模块前缀>_<语义>`，如 `BP_ENQUEUE` / `EU_SPLICE` / `IV_COUNTER_PICK`。
- 新增帧类型必须：
  1. 在 `src/engine/AnimFrame.h` 的 `ActionType` 末尾追加（不要插在中间，避免破坏既有枚举值）；
  2. 在模块的 `runAlgorithm()` 里生成；
  3. 在 `renderFrame()` 里处理；
  4. 补一条测试断言。
- 帧数据复用 `AnimFrame` 的既有字段（`u/v/val1/val2/group`），**不要**为每个模块新造结构体。

## 8. 新模块动画自检清单 (Checklist)

写完一个模块后逐条核对：

- [ ] 数组下标在格子**上方**，值在格子**正中**
- [ ] 所有指针尖端精确落在格心 / 节点圆周
- [ ] 指针标签不互相重叠、不越出画布
- [ ] 指针换锚点时**有可见的平移过程**，不是瞬移（见 2.3 强制条款）
- [ ] 颜色语义符合本文第 1 节
- [ ] 「从 u 到 v」的运动使用了 `playEdgeTravelFrom` 并传了起点 id
- [ ] 队列 / 栈在流程结束时已清空
- [ ] 递归分治类算法：区间**真的裂开**（有物理缝隙），合并完成**真的拼接**（合缝 + 整段变绿）（见 3.4）
- [ ] 并查集类：`pa[]` 初始全为自身下标、`sz[]` 初始全为 1，两数组逐格对齐（见 3.5）
- [ ] 画面有明确的结论文本
- [ ] `m_animated = false` 时无任何属性动画被创建
- [ ] 动画回调捕获的对象指针必须是 `QPointer`，不得裸指针（防画布清空后崩溃）
- [ ] `SmartGroundStrictAudit` 的三项计数全为 0
- [ ] 新增/变更的模块在 `docs/ModuleStatus.md` 与 `docs/BugLog.md` 有记录

## 9. 坐标系画布语义 (Cartesian Canvas)

笛卡尔坐标系是**自由结构**而非算法模块，但同样受本宪法约束。以下条款为该类画布的**硬性标准**。

### 9.1 无限网格与视口裁剪

- 坐标系在数学上是**无限延伸**的，屏幕上只绘制**当前视口覆盖的那一小块**。
- 网格图元的 `boundingRect()` 必须**跟随视口**（可预留少量余量），**禁止**用一个巨大的固定包围盒（如 ±2000000）——那会让场景索引与碰撞检测退化。
- **「无限」的正确实现是「视口驱动」而不是「数组开大」**：网格线的起止与条数**必须由当前视口的数学范围动态算出**，绝不预生成固定数量的网格线。同时 `CanvasView::scrollContentsBy()` 覆写为**在滚动时同步视口**，保证平移后网格立即跟上来。
- 画布的 `sceneRect` 在坐标系模式下**必须解除内容包围盒限制**（`ViewportFitter::setInfiniteCanvas()` 置为 ±1e7 的场景矩形），否则 `expandSceneRect()` 依据 `itemsBoundingRect()` 算出的矩形会把**平移范围死死卡住**，表现为「坐标系延伸到某个数就结束」。
- 判据：把原点平移 10 万个单位以后，网格的**绘制像素数应与原点处基本一致**（`SmartGroundCartesianGridExtent` 断言此性质）。
- 网格是**背景层**（`z = -1000`），永远压在点 / 线段 / 曲线之下。

### 9.2 分度尺 (Ruler) 语义

- 分度尺不是固定值，而是随缩放**在固定阶梯上跳变**：`100 / 50 / 20 / 10 / 5 / 2 / 1 / 0.5 / 0.2 / 0.1 / 0.05 / 0.02 / 0.01`。
- 选档规则：**像素间距 ≤ 62px** 的最大档位。像素间距过密会让网格变成灰糊一片，过疏会让「粗线交点」难以辨认。
- 主网格线（当前分度尺）与次网格线（分度尺 ÷ 5）**颜色必须分层**：主线 `#E0E6F0`，次线 `#F0F3F9`；次线在像素间距 < 6px 时**不绘制**。
- 坐标轴用更深的中性灰（`#7E8A9C`）且线宽略粗，**刻度数字**用更浅的灰（`#8E98A8`），保证轴与网格不抢视觉重心。

### 9.3 几何事实的呈现

- **描点默认是「接近吸附」而非「强制量化」**：只有当光标**靠近**当前分度尺的粗线交点（距离 ≤ 0.28 个分度尺单位）时才吸附到该交点；否则**保留自由坐标**（例如分度尺为 1 时可以落 `(0.5, 0.8)`）。硬量化（`round(x / step) * step`）会剥夺「任意坐标」这一 GeoGebra 式的表达力，**禁止**使用。
  - 实现上必须把「吸附」与「量化」拆开：`snappedMath()` 做接近判定，`isSnapped()` 让调用方能区分「吸附点」与「自由点」；信息面板要显式告诉用户当前这个点**是否已吸附**。
- 点的名字标签用**白底圆角小卡片**紧贴点的右上角，颜色取点色加深版；「隐藏名字」是**每个点独立的属性**，不是一个全局开关。
- **几何事实默认不直接压在图上**：线段的一次方程 `y = kx + b` 与曲线方程**不常驻绘制**（白底卡片会遮挡图面、干扰讲课），而是**双击时在右侧检视面板中呈现**。「几何事实要呈现」指的是**可随时查到**，而不是**一直画着**；用户在设置里显式勾选时才画回图上。
- 曲线的方程同理，双击曲线在检视面板中呈现。

### 9.4 曲线的可视范围语义

- 函数曲线**按当前视口的数学范围自适应采样**，而不是预先算好一张固定的图。
- 曲线**平移出视口即消失，平移回来即恢复** —— 这是「无限坐标系」的关键体感，不得用「固定图 + 裁剪」代替。
- 采样遇到**出界**时，只**切断当前这一段**，**绝不清空整条曲线**。抛物线在视口内必然先下探后回升，整条清空会导致「二次函数整条看不见」。
- 采样段数随跨度自适应（窄视口少采样、宽视口多采样），单段最多 900 点。

### 9.5 低延迟硬性要求

> 坐标系属于**直接操控型**画布，延迟红线是 **60fps**（单帧 ≤ 16ms）。

- 坐标系内所有图形对象必须是**原生 `QGraphicsObject`**，直接接管鼠标事件；**禁止**用 `QPropertyAnimation` 做拖动跟随。
- 拖动跟手时每帧只做：改数学坐标 → `setPos()` → `update()`。不做任何额外的重绘广播。
- 滚动 / 平移导致的曲线重算必须**增量**：只重算可见范围，不重建整个场景。
- **判据**：描点拖动出现肉眼可见的「跟手延迟」即为违反本条款。

### 9.6 坐标系的对象列表面板

- 左侧面板列出**全部**对象（点 + 函数），每行至少给出：颜色标识、名字、坐标 / 表达式、更多菜单入口。
- 「更多」菜单的项**按 GeoGebra 对标**只提供：**编辑名称与坐标** / **设置** / **删除**。**不引入「高级」「脚本」**等本项目不具备的能力。
- 样式设置卡必须复用项目既有的**无极变色**框架（`MyColorPicker`）、`MySlider`（大小）、`MySegmentedControl`（形状）、`MyToggleSwitch`（隐藏名字），**不得**另起一套控件。
- 开关语义遵循第 4.1 节：滑块在右 = 该状态开启。

### 9.7 坐标系专属工具行与可发现性

- 坐标系工具（画点 / 连线 / 函数）放在浮动工具栏的**第二排**，与算法工具行**上下分离、绝不重叠**。排版用**绝对定位**：主行 `(0, 0)`，坐标系行 `(0, mainH)`，工具栏总高 `mainH + cartH`。
- 第二排的每个图标**必须带中文文字标签**（「画点 / 连线 / 函数」）。**无文字的图标按钮不构成可发现性** —— 圆形、正方形这些符号对初学者没有语义。
- **文字标签必须与图标属于同一个可点击控件**。把图标做成按钮、文字做成独立的 `QLabel`，等于「只有 30×30 的图标能点」，判定区域过于苛刻 —— 用户瞄准文字却毫无反应。正确做法是让 `ToolIconButton` 支持内嵌文字（`setCaption()`）：文字**画在按钮内部**并**参与尺寸计算**，图标与文字共享同一块命中区，选中态（accent 圆角底 + 反白文字）也整体高亮。
- 图标的 tooltip 承诺的快捷键**必须真实存在**。承诺 `(P)` / `(S)` 就要在 `keyPressEvent` 里实现，键位只在坐标系模式下生效。
- 进入坐标系模块时**自动选中画点工具**：用户进入模块后的第一动作就该是能做的事，而不是先去工具栏里认图标。
- 画点 / 连线这类工具**必须消费鼠标事件**。若工具未列入 `isDrawingTool()`，画布会吞掉点击，表现为「点了没反应」。
- **画点 / 连线模式下，按住鼠标右键拖动必须平移画布**。直接操控型画布里，视图平移不能只绑定中键与空格 —— 用户右手拿笔时右手无法同时按中键。右键平移与右键擦除互斥：坐标系启用时右键一律平移。

### 9.8 坐标系的操作引导卡 (GuideCard)

- 坐标系面板顶部必须挂一张**四步引导卡**：画点 → 连线 → 函数 → 管理。步骤序号用**实心圆角徽章**（accent 底 + 白字），标题加粗，细节用弱化灰。
- 引导卡是**一次性常驻**的静态说明，不是动画。它回答的是「我从哪儿开始、怎么操作」，颜色语义见第 9.8.1 节。

#### 9.8.1 引导卡的色彩语义

| 元素 | 颜色 | 表达的语义 |
|---|---|---|
| 卡片底 | `UiTheme::accentSoft()` 半透明 | 「这是操作提示，不是数据」 |
| 卡片描边 | `UiTheme::borderSoft()` | 与数据区分 |
| 序号徽章 | `UiTheme::accent()` + 白字 | 「这是第几步」 |
| 步骤标题 | `textPrimary` 加粗 | 「这一步要做什么」 |
| 步骤细节 | `#7A8494` | 「具体怎么做」 |

### 9.9 坐标系模式下的全局控件裁剪

- 进入坐标系模块时，**算法专属控件必须全部隐藏**：算法输入框、构建按钮、单步 / 自动播放按钮、脚本文字开关、对齐网格开关。
- 对齐网格（`SceneGrid`）在坐标系下**必须关闭**：它按固定 56px 画对齐辅助线，与坐标系自己的数学网格（随分度尺变化）语义冲突、视觉打架。
- `SceneGrid::Config` 是**全局静态状态**，切换模块时必须**显式重置**，不能指望它自己恢复默认值。
- 判据：坐标系模式下左侧除「模块下拉 / 坐标系设置 / 对象列表 / 函数绘制」外，不应出现任何算法控件。

### 9.10 函数录入的表达宽容度

- 函数输入框必须**接受教科书写法**：解析器要剥离 `f(x) =` / `y =` / `f =` 前缀后再求值，用户照抄课本公式不应报错。
- 输入框**回车即绘制**（`editingFinished`），并提供**实时解析反馈**：绿字显示「将绘制：…」的规范式，红字显示「无法解析：…」及原因。
- 表达式输入框**不套用第 4.3 节**「只在 `editingFinished` 写回状态」的约束 —— 那条针对的是会触发整场算法重跑的输入；函数表达式只新增一条曲线，回车提交是正确交互。

### 9.11 右侧检视面板 (Inspector)

- 双击画布对象**不能弹出模态对话框**。模态框会遮挡整块画布、打断讲课节奏，把「查看信息」变成「必须先关闭才能继续」。
- 双击对象必须在**画布右侧弹出轻量浮层**，自绘圆角白卡（不使用原生 `QMessageBox` / `QDialog`）。结构固定三段：**标题**（对象名）→ **正文**（等宽字体的事实数据）→ **提示行**（弱化灰的一句话补充）。
- 面板必须**始终锚在画布右半区**且**不出界**，纵向大致居中。它是**浮层**（覆盖在画布上）而不是**布局成员** —— 布局成员会把画布挤窄，导致「弹个信息框画布就变形」。
- 承载内容：
  | 对象 | 标题 | 正文 | 提示 |
  |---|---|---|---|
  | 点 | `点 A` | `x = …` / `y = …` | 是否已吸附到交点 |
  | 线段 | `线段` | `y = kx + b` | 线段长度 |
  | 曲线 | `函数 f` | `y = 表达式` | 去左侧对象列表修改 |
- **「检视」与「编辑」必须是两条独立通路**。双击 = 检视（只读，右侧浮层）；左侧列表的 ⋮ 菜单 = 编辑（模态对话框，改名字 / 坐标 / 样式）。两者混用会让用户双击一下就被弹窗打断。

### 9.12 坐标系对象列表的实时性

- 左侧对象列表必须在**任何**改变对象的操作后**立即刷新**：画布上描点、拖动点、连线、删除点、增删函数。
- 根因防线：**信号连接必须在对象真正创建之后建立**。若连接代码跑在模块实例化之前，`if (module) { connect(...) }` 里的整段会静默跳过，表现为「功能完全正常但列表永远不更新」。
- 点坐标在**拖动过程中**也在变，因此 `setMathPos()` 必须在**位移真正发生时**发出通知，而不是只在初始化时通知一次。

### 9.13 交互行为的验收方式（真实事件链）

- **验收「画布交互类」功能时，测试必须驱动真实鼠标事件链**，不得直接调用引擎 / 模型的 API 来断言。真实链路是：`QGraphicsView` → `viewport` 事件过滤器 → `ToolController` → 引擎 → `MainWindow` 槽函数 → 面板刷新。任何一环断掉，**直接调 API 的测试依然是绿的**，而用户看到的是「点了没反应」。
- 典型反例：`engine->addPoint()` 后断言列表行数增加 —— 这只验证了「引擎加了点会发信号」，**完全没验证「用户点画布会加点」**。而后者才是会出问题的环节（事件未被消费、工具未激活、过滤器顺序不对）。
- 必须用真实事件覆盖的交互：**单击落点 / 拖动改点 / 双击检视 / 右键平移 / 点击工具按钮（含文字标签）/ 键盘快捷键**。
- 渲染类断言（网格密度、曲线可见性、面板位置）应采用**相对判据**而非绝对阈值：例如「平移 10 万单位后网格像素数与原点处一致」比「网格像素数 > 500」更贴近真实不变式，也不会因视口尺寸、缩放档位变化而误报。
